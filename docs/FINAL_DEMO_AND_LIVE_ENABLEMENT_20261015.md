# OhMySmell – демонстрация и условия запуска (15.10.2026)

## Работает в production

- Сайт Tilda: заказ попадает в CRM. Клиентский Telegram-бот показывает товары и статус.
- Клиентская **оптовая Gmail** – отдельный read-only OAuth. Новые письма классифицируются как заказ / вопрос / возможный заказ; HTML-таблицы с артикулами, ценами в ₽ или $, количеством, итогом и шапкой баланса разбираются. **Валютная цена из письма не переписывает цену в CRM** – продажи рассчитываются по оптовому прайсу МойСклад после сопоставления.
- Менеджерский Telegram: проверка товара/количества/контрагента, восстановление неверно классифицированного письма, подтверждение или закрытие.
- Контрагенты: сверка по email, имени, ИНН; ручной поиск `/cpsearch`, разбор `/cpcheck`, осторожное создание по `/newcp` с журналом и защитой от дублей.
- Buying: backend/API, роли Manager/Picker, каталоги, корзины и оформление внутренних закупок, с тестами; **почта поставщиков не подключена**. Production supplier-email worker запущен в `supplier_email_dormant`, не вызывает Gmail, не отправляет письма и не изменяет данные.

## Проверено в тестах, ещё не включено для настоящих складских операций

- Сайт Tilda → менеджер назначает свой склад или склад Х → сборщик физически подтверждает сборку → на Х: одно внутреннее оприходование `enter` со стоимостью **продажа Tilda минус 1 000 ₽/шт.** → по каждому складу отдельный резерв и отгрузка.
- Контрагент Хатуна в этом варианте **не агент платёжных документов**: нет заказа поставщику, долга, приёмки у поставщика и писем Хатуне. Пометка «Хатуна» – в описании учётного оприходования. Организация WowHairLover – только необходимый внутренний реквизит МойСклад.
- В журнале внешних операций – детерминированные ключи, блокирование слепого повторного POST, фиксация неопределённого ответа. Нельзя вручную подтвердить приход/закупочную цену Х в режиме post-pick.
- На товары отсутствующие в каталоге МойСклад либо уже учтённые на Х требуется **ручная сверка** и создание/сопоставление карточки без дубля перед live-учётом. Проводки в production отключены, пока нет доказанного сквозного сценария по конкретному заказу и складу.
- Флаги `OMS_HATUNA_POST_PICK_ENABLED`, `OMS_HATUNA_AUTO_PROCESS_ENABLED`, `OMS_HATUNA_AUTO_WRITES_ENABLED` и `EXTERNAL_WRITES_ENABLED` **не включать одной операцией**. Включение реальных записей только после согласования владельца, прогона read-only preflight, отдельного безопасного заказа и сохранённых скриншотов документов МойСклад.

## Как пользоваться (коротко)

1. Менеджер открывает заявку в Telegram, проверяет источник (Tilda/Gmail), название, артикул, количество и оптовую/розничную цену.
2. Для Gmail: если это уточнение – отвечает из исходной переписки. Если заказ – сверяет товар по имени/артикулу с МойСклад, выбирает контрагента. При недостающих реквизитах запросить данные клиента.
3. Контрагент: `/cpcheck НОМЕР` / `/cpsearch НОМЕР НАЗВАНИЕ_ИЛИ_ИНН` / `/newcp НОМЕР ПОЛНОЕ_НАЗВАНИЕ`. Существующие записи не дублировать.
4. Для Tilda: назначить источники – только основной склад либо склад Х. Если товара нет в МойСклад, остановить автоматические документы и сопоставить/создать карточку без дубля.
5. После физической сборки – запускать складские документы только если организация, склады, каталог и preflight подтверждены. В остальных случаях удерживать заказ на ручной проверке.
6. Buying – отдельный внутренний закупочный процесс; не подменять им склад Х и не использовать клиентскую почту для заказов поставщикам.

## Как добавить сотрудника в менеджерскую группу

- Создать закрытую Telegram-группу, добавить менеджерского бота.
- Установить в production Railway Manager Bot: `MANAGER_TELEGRAM_MODE=group`, `MANAGER_TELEGRAM_CHAT_ID=-100...`, `MANAGER_TELEGRAM_USER_IDS=ID1,ID2,...` (числовые Telegram ID).
- Добавить каждого разрешённого человека в таблицу `managers`: внутри среды с рабочей production DATABASE_URL вызвать

```bash
python -m scripts.manage_manager_access --telegram-id 123456789 --name "Иван" --confirm --production
```

- Проверить, что оба барьера доступа – Telegram ID в allowlist и активная запись менеджера – сработали; затем проверить получение карточки в нужной группе.
- Для отключения сотрудника использовать ту же команду с `--disable` и удалить ID из `MANAGER_TELEGRAM_USER_IDS`. При добавлении только в группу доступ к кнопкам не появляется.
